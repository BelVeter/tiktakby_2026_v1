# Скорость главной на мобильных (ноябрь 2026)

**Повод (21.11.2026):** при первом заходе с телефона (Galaxy S23, Беларусь) главная `tiktak.by/ru`
грузилась «очень медленно».

**Вывод:** сервер ни при чём (TTFB ~0.2 с). Главная при пустом кэше качает **4.4–6.1 МБ за
~235 запросов**; на слабом 4G полная загрузка — **23 с**, первый баннер слайдера — **13 с**.
Повторные заходы быстрые (всё из кэша), поэтому постоянные посетители проблему не видят.

Источники: свой Lighthouse (mobile, 2 прогона), замер в Chrome с троттлингом, независимый
разбор другого ИИ-агента (PageSpeed Insights + исходники). Пункты другого агента сверены с
кодом; где не проверено — помечено.

## Что нашли

1. **8 битых картинок** (отзывы ×3, блок Instagram ×6 → 8 уникальных URL). Каждая 404 уходит в
   Laravel (у `public/.htaccess` свой `RewriteEngine`, правило корня «статику — мимо PHP» не
   действует) и отдаёт HTML-страницу 404 на 212 КБ. Итого ~1.7 МБ и 8 PHP-запросов на заход.
2. **Слайдер — инверсия приоритетов.** Это горизонтальная лента (scroll-snap), все 6 слайдов в
   HTML сразу. `fetchpriority="high"` остался на закомментированном premium-start и на 5-м и
   6-м (невидимых) слайдах; у первого видимого — нет. Мобильные картинки слайдера уже отдельные
   (`*-mob.webp`, 800×600, 27–68 КБ) — отдельный мобильный слайдер **не нужен**, нужен порядок.
3. **`loading="lazy"` — у 1 из 281 картинки.** Телефон сразу качает всё: скрытые меню каталога
   (мобильное и десктопное мега-меню), 125 логотипов брендов внизу, «Популярные товары».
4. **Тяжёлые картинки:**
   - иконки категорий (`public/png/*.png`, показываются 75–130 px) — 790 КБ;
   - «Популярные товары» (пути из БД, грузятся через админку) — 906 КБ, из них
     `4momsmamaroosleep_bassinet4.jpg` 1000×1000 — 528 КБ;
   - «псевдо-SVG» с PNG внутри: `toys_back_mobile.svg` 150 КБ (фон отзывов), `toys_back.svg`
     196 КБ (то же, десктоп), `webitconnection-logo.svg` 119 КБ (логотип 50×50 с PNG
     1613×1617 внутри), `star-review.svg` 47 КБ (звёздочка 17×16), `geo_logo.svg` 33 КБ (15×20).
5. **Шрифты:** Roboto подключён дважды, Nunito — все 16 начертаний, Roboto — все 12;
   Font Awesome с CDN; локальные `.otf/.ttf` без `font-display`.
6. **JS:** в `app.js` целиком `lodash` и `axios`; `popper`, `bootstrap`, `app.js` без `defer`.
7. **Аналитика** (2 gtag + Метрика с Вебвизором) в начале `<head>`: ~400 КБ, ~0.9 с CPU.
8. **Бэкенд:** редирект `/` → `/ru` через PHP-контроллер; блок «Популярные товары» зовёт
   некэшированный `getUrlL3Page()`; `TopMenu` без кэша (не проверено); 82 КБ скрытого
   десктопного мега-меню в мобильном HTML.
9. **Мусор в git:** `public/slider/*.ppm`, файл `public/slider/I` (не используются).
   Картинки слайдера (`*.webp`) в git **не** лежат — их заливали на прод вручную.

## Решение: переписывать ли слайдер

Вопрос владельца: оставить в HTML один слайд, остальные добавлять скриптом после полной загрузки.
Замер (локально, слабый 4G, 3 прогона, вариант с JS сымитирован задержкой запросов слайдов 2–6
до `load`): первый экран **1.19–1.24 с** (текущее решение) против **1.16–1.21 с** (JS) — разница
0.03 с, незаметна. Минусы JS-варианта: край 2-го слайда виден на телефоне сразу и был бы пустым,
больше кода, при ошибке JS слайдер из одного слайда. **Решение: не переписывать**, хватает
приоритетов (п. 1.2). Отдельный мобильный слайдер тоже не нужен: `*-mob.webp` уже 800×600, 27–68 КБ.
