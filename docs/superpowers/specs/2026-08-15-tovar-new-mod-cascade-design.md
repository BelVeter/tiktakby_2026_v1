# Каскад категория/фирма/модель + вкладки создание/редактирование — спецификация

**Дата:** 15.08.2026
**Ветка:** `feature/producers-directory`
**Продолжает:** `docs/superpowers/specs/2026-08-14-producers-directory-design.md` (раздел «Не в объёме»:
«Замена `<select>` моделей (около 1800 позиций) на живой поиск — следующий шаг») и
`docs/superpowers/plans/2026-07-27-tovar-new-mod-hardening.md` (Фаза 7)

---

## Задача

На `bb/tovar_new_mod.php` три поля — категория, фирма, модель — сейчас никак не связаны
между собой, кроме сортировки подсказок фирмы по категории (сделано в прошлой итерации).
Поле «Модель» — нативный `<select>` со **всеми** ~1800 именами моделей в базе, без всякой
фильтрации, и служит только защитой от опечатки в названии при вводе нового имени.

Настоящая проверка на дубль происходит только на сервере в момент нажатия «сохранить»
(`tovar_new_mod.php:123`): если найдётся точь-в-точь такая же запись (категория + фирма +
модель + **цвет**), новая модель не создаётся — используется существующий `tovar_rent_id`,
а всё, что сотрудник успел ввести в остальные поля (цена, комплектация, возраст, вес),
молча теряется. Обнаружить это можно только постфактум, по тексту после сабмита.

Кроме того, у живого поиска категории/фирмы на этой странице нет полного списка «по
клику» — только поиск по набранным буквам (порог `minQuery: 1`), хотя виджет
(`live_picker.js`) это умеет — просто не включено здесь.

Отдельная, обнаруженная по ходу разработки проблема самого виджета: `LivePicker` не
синхронизирует текст поля со скрытым значением при потере фокуса без выбора варианта —
если начать печатать поверх уже выбранного значения и передумать, скрытое поле держит
старое значение, а видимый текст — недопечатанное. Раньше это редко всплывало, но по мере
того как поля перестают взаимно сбрасываться, риск растёт.

---

## Решение

### Две вкладки: «Новая модель» / «Редактировать действующую»

Формализует то, что на сервере уже есть (`action=сохранить` / `action=обновить` —
`tovar_new_mod.php:90,204`), но раньше было доступно для редактирования только по прямой
ссылке с готовым `model_id` (кнопка «редактировать модель» на `tovar_new.php`). Теперь то
же самое достижимо поиском, с нуля.

Категория и фирма — общие поля для обеих вкладок, их виджеты не дублируются. Меняется
только поведение поля «Модель» и то, какое значение `action` уходит на сервер при сабмите
(переключается вместе с текстом кнопки).

Если страница открыта с готовым `model_id` (переход по существующей ссылке
«редактировать модель») — вкладка «Редактировать» выбрана сразу, поиск не нужен, форма
заполнена как сегодня.

### Категория и фирма: полный список по фокусу

`minQuery: 0` — как уже сделано у фирмы на `tovar_new.php`. Сейчас `ajax_category_suggest.php`
и `ajax_producer_suggest.php` при пустом `q` отдают `items: []` (путь не был нужен, пока
поле требовало ввода) — научить отдавать полный список: 115 категорий и ~370 производителей
нормально скроллятся в уже существующем `.catp__results` (там же есть `overflow-y: auto` и
авто-подгонка высоты под экран).

### Поле «Модель»: один текстовый живой поиск вместо `<select>` + `<input>`

Новый эндпоинт `bb/ajax_model_suggest.php`: принимает `q` (подстрока по имени модели),
опционально `cat_id` и `producer` — фильтрует по тем, что заданы (`AND`, не заданные
игнорируются). Отдаёт **полные строки** `tovar_rent` (по одной на каждую комбинацию
категория+фирма+модель+**цвет**, то есть на каждый `tovar_rent_id`) — включая `dog_name`
категории, нужный для авто-заполнения поля «для договора» при жёстком выборе категории.

Ключевое отличие от категории/фирмы: у модели нет модалки «создать». Свободно введённое
имя, не совпавшее ни с одной подсказкой, — штатный путь, не ошибка: значит, модели с таким
именем ещё нет.

Полный список по пустому фокусу (`minQuery: 0`) здесь не подходит буквально: категорий 115,
производителей ~370 — оба списка нормально смотрятся целиком, а уникальных комбинаций
категория+фирма+модель+цвет — 1627, вываливать их все по клику на пустое поле бессмысленно.
Поэтому: если уже выбраны категория и/или фирма — подсказки по пустому запросу показывают
полный отфильтрованный список (обычно единицы-десятки строк, смотреть их целиком уже
нормально); если не выбрано ни то ни другое — пустой запрос ничего не показывает, только
подсказку «начните вводить название или сначала выберите категорию/фирму». Набор ≥1 символа
всегда ищет по всей базе, независимо от того, что выбрано.

**Вкладка «Новая модель».** Подсказки схлопываются на клиенте по имени (цвет не показывается
отдельной строкой — на этой вкладке он не важен для выбора, он вводится позже вручную).
Выбор варианта жёстко проставляет категорию и фирму (аналогично тому, как сейчас работает
попап создания категории/фирмы — через `picker.choose(item)`), но **не** трогает остальные
поля формы — они остаются такими, какими их ввёл сотрудник. Если набранное имя точно
совпадает с уже существующей записью в выбранных категории+фирме — рядом появляется
подсказка «Такая модель уже есть (цвета: …) — редактировать?» со ссылкой, переключающей на
вкладку «Редактировать» с тем же именем в поиске. Без клика ничего не меняется — решение
всегда за человеком, тот же принцип, что уже применён к дублям категорий и производителей.

**Вкладка «Редактировать действующую».** Подсказки показываются как есть, по одной строке
на `tovar_rent_id`, с цветом во второй строке для различения («Fox · Bugaboo · Коляски
3-в-1 · красный»). Выбор варианта жёстко проставляет категорию, фирму и **все** остальные
поля формы (цвет, комплектация, цена, возраст, вес, пол, карнавальные поля) — редактируемо,
как сегодняшний `action=редактировать`. Также записывает `tovar_rent_id` в скрытое поле
`model_id`, которое `case 'обновить'` уже использует как условие `WHERE`.

### Рассинхрон текста и значения (доводка `live_picker.js`)

На потере фокуса, если текст в поле не совпадает с именем последнего выбранного варианта:
если поле пустое — это явный сброс выбора; если непустое, но не выбрано — откатить текст к
последнему выбранному значению. Правится один раз в общем `live_picker.js`, работает
одинаково для категории, фирмы и новой модели. Отдельной кнопки «очистить» не заводим — она
не нужна: обнуление через стирание текста уже покрывает случай.

### Клиентская валидация

`send_form_ch()` (`tovar_new_mod.php:327`) переключается на проверку нового единого поля
модели вместо пары `model_select_new`/`model_input_new`.

## Осознанные компромиссы

**Один эндпоинт на обе вкладки.** `ajax_model_suggest.php` всегда отдаёт полную строку
(включая цвет), различие между вкладками — только в том, как клиентский JS группирует и
показывает результат. Это проще, чем два отдельных режима на сервере, и не создаёт
рассинхрона между тем, что видят вкладки.

**Подсказка о дубле на вкладке «Новая модель» не проверяет цвет.** Совпадение по
имени+категории+фирме уже даёт достаточно уверенности, чтобы предложить переключиться на
редактирование; сотрудник увидит все существующие цвета в подсказке-ссылке и решит сам,
дубль это или новый цвет.

**`tovar_new.php` (страница добавления единицы товара к существующей модели) в объём не
входит** — отдельная задача, отложена. Взаимосвязь категория/фирма/модель там устроена
иначе (там выбор модели не создаёт, а находит существующую запись для привязки товара) и не
обсуждалась в этом раунде.

## Не в объёме

- Всё, что касается `tovar_new.php`.
- Разбор карнавальной свалки в поле `producer` — вне этой задачи (см. предыдущую спеку).
- Отдельная кнопка явной очистки поля — покрыто доводкой рассинхрона.

---

## Тесты

- `ajax_model_suggest.php`: фильтрация по `q`/`cat_id`/`producer` по отдельности, по всем
  вместе и без единого фильтра; корректная отдача `dog_name` категории; экранирование
  входных параметров в SQL; пустой `q` без категории и без фирмы — пустой список; пустой `q`
  с категорией и/или фирмой — полный отфильтрованный список без обрезки.
- Живой каскад на странице (smoke, как в прошлой итерации): жёсткий выбор категории/фирмы
  по клику на модель на обеих вкладках; переключение вкладки меняет `action` на кнопке;
  вход с готовым `model_id` сразу открывает вкладку «Редактировать»; подсказка о дубле на
  вкладке «Новая модель» появляется только при точном совпадении и не блокирует сохранение.
- `live_picker.js`: рассинхрон на потере фокуса — откат к последнему выбору / сброс при
  пустом поле.

## Порядок работ

Работа идёт локально, на ветке `feature/producers-directory` (прод не трогаем, см.
`docs/prod_pending.md`).

1. Доводка `live_picker.js`: синхронизация на потере фокуса.
2. `minQuery: 0` + полный список по пустому `q` в `ajax_category_suggest.php` /
   `ajax_producer_suggest.php`.
3. Новый эндпоинт `ajax_model_suggest.php`.
4. Разметка и JS вкладок на `tovar_new_mod.php`, живой поиск модели на обеих вкладках,
   обновлённая клиентская валидация.
5. Обновить `docs/prod_pending.md`.
