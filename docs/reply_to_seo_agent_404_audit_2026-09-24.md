## 4. Что не сделано и почему

- **Политика для моделей без единиц** (404 как сейчас или 200 «нет в наличии»): продуктовое решение владельца,
  затрагивает 53 из 470 «мёртвых» URL и повторяющиеся 404 при распродаже.
- **Sitemap:** исключить категорию Биоптрона (301) и слаг с пробелом (`pelenalnyj_stolik _s_vannochkoj_cam_cambio`;
  `&` в `laugh_&_learn_smart_stages_home` в XML записывается как `&amp;` и валиден — но `<link rel="canonical">`
  этих двух страниц содержит пробел/`&` в сыром виде, поэтому корректнее переименовать слаги); убрать дубли по M:N
  (≈51 адрес подраздела `begovely_velosipedy_samokaty` под чужим разделом `prokat-sports`) — сделано в ветке
  `fix/sitemap-generator-canonical`, ждёт PR и выкатки (`sitemap.xml` вне git уже выкачен, см. раздел 3, п. 10).
- **Таблица «URL → 301/404» для 470 мёртвых** и аудит целей всех 765 редиректов — после решения по задаче 1.
- **Битые декоративные картинки** (раздел 5) — нужно решение: восстановить файлы из бэкапа старого хостинга
  или убрать теги `<img>` из описаний.
- **Судьба десяти моделей «К УДАЛЕНИЮ»:** перенос в карнавальные категории или списание единиц и
  архивация (`ModelArchive`) — зависит от того, есть ли вещи физически.
- **`sling_…_s_2.jpg`** — дефекта страницы нет, не исправлялось.

## 5. Новые находки вне вашего промпта

1. **Soft-404 на выдуманную категорию.** Любой несуществующий слаг третьего сегмента под настоящим разделом и
   подразделом (`/ru/prokat-detskih-tovarov/kolyaski-detskie/zzzz`) отдаёт **200** со страницей «Раздел не
   найден.». Причина: `MainPage::isRealPage()` считает страницу настоящей, если найден только раздел.
   Воспроизводится и до моих изменений. Заведено в backlog, самый весомый следующий кандидат.
2. **Потерянные картинки в контенте.** Скан всех локальных `src` в описаниях, FAQ и текстах страниц: 37 уникальных путей
   (34 абсолютных и 3 относительных); из абсолютных **33 отдают 404** (один из них — новый путь значка «Важно»
   до выкатки ветки `feat/vazhno-icon`), то есть 32 по-настоящему потерянных. Это каталоги `bb/img/*` (гифки костюмов), `karnaval/img/*`,
   `vesy/img/*`, `public/rent/images/autokresla-bases/maxi_cosi_easybase/*`. Каталоги на проде отсутствуют,
   в git никогда не отслеживались (картинки под `.gitignore`), в истории их нет — по-видимому, не переехали на
   новый хостинг в июне. Затронуто ≈35 карточек (id 13, 60, 73, 75, 248, 345, 349, 368, 412, 417, 421, 423, 428,
   430, 432, 433, 734–738, 740, 749, 951, 954, 979, 1154, 1351, 1420, 1483, 1514, 1516, 1520, 1740, 1854) и страницы
   `pages` id 42, 45, 50, 67. За 10 дней около 300 запросов на эти файлы, треть с referrer (реальные посетители).
3. **Служебная категория `tyu` («К УДАЛЕНИЮ»)**: остаток миграции старого сайта, в меню не видна, но сайт сам
   строил на неё ссылки (рекомендации на медицинских страницах, поиск, sitemap), 11 заявок за год. Скрыта (см. п. 3).
4. **`not_show` не закрывает прямой адрес:** `ModelWeb::getByUrlName()` статус не фильтрует, карточка открывается по
   слагу при любом префиксе. Честный 404 даёт только архивация (`ModelArchive`) или отсутствие единиц.
5. **Каноническая цепочка URL** у сайта одноцепочечная (категория → `main_sub_razdel_id` → `sub_razdel.main_razdel_id`),
   а sitemap и часть кода строят адреса через M:N — отсюда дубли URL (например, `/prokat-detskih-tovarov/` и
   `/prokat-sports/` для одной категории) и 14% моделей с неканоническим адресом в старом API.
6. **18 из 111 категорий вне `subrazdel_category`** (не видны в меню): помимо `tyu` живые товары есть у
   `tolshchinomery` (2) и `aksessuary-dla-samokatov` (1) — намеренно ли, неизвестно.
7. **Недостижимый контент:** `pages` id 25 (категория «конверты на выписку») за редиректом и содержит три
   относительные ссылки `../vesy/vesy.htm`, которые на странице вели бы на выдуманные 200-страницы; страница

9. **Разовый 500 на карточке** (`novogodniy_costum_dlya_malchika_bury_medved`, 25.09 15:44:40 при обходе sitemap в 6 потоков сразу после деплоя): `file_put_contents(storage/framework/cache/data/…): No such file or directory` в `Cache::remember('rec_view_ids_…')` (`L3Page.php:333`). ## 7. Замечания к методике аудита (чтобы следующие выгрузки были точнее)

- Логи прода — на сервере (`/var/www/h149208/data/logs/`), хранятся с 13.09; путь `~/logs/…` из вашего промпта
  на рабочей машине не существует. Строки логов **дублируются** (два формата), считайте запросы с поправкой.
- «Мигание» по редким хитам ботов не диагностируется: смотрите состояние БД (`tovar_rent_items`,
  `tovar_rent_items_arch`, даты `arch_time`) и таймлайн статусов по логам.
- Флаг `in_sitemap` зависит от момента снятия: до выкатки `fix/sitemap-out-of-git` сразу после деплоя отдавалась закоммиченная версия файла (после неё файл деплоем не откатывается).
- Прежде чем предлагать правку «в шаблонах», проверяйте, не лежит ли текст в БД (`pages`, `rent_model_web`);
  правки контента — через MCP API (`/pages/product/bulk`, `/redirects`), но не для `pages` главной.
