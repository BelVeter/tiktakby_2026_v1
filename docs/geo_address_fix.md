# Разбор нераспознанных адресов клиентов (geo_status=2)

> Методика ручного/AI-ассистированного исправления адресов, которые не смог разобрать геокодер (Google Maps, с fallback на Яндекс). Читать перед повторным прогоном разбора «глючных» адресов на карте клиентов (`bb/geo_heatmap.php`). Первый прогон — 2026-07-05, разобрано 37 адресов, 28 исправлено автоматически.

## Зачем это нужно

`clients_geo.geo_status` — статус геокодирования адреса клиента (`app/Console/Commands/GeocodeClients.php`):
- `1` — координаты найдены и им можно доверять (используется в тепловой карте `bb/geo_heatmap.php`)
- `2` — не распознано ни Google, ни Яндексом. Крон повторяет попытку раз в 7 дней **с тем же сырым адресом** — если причина в опечатке/сокращении в самих данных клиента, повтор ничего не даст без правки.

Большинство `geo_status=2` — не мусорные адреса, а нормальные адреса, записанные call-центром в разговорной/сокращённой форме, которую строгий геокодер не понимает (см. дальше).

## Шаг 1 — выгрузить нераспознанные адреса

Через SSH на проде (см. `~/.claude/projects/.../memory/reference_ssh_production.md` — доступ только с согласия пользователя в чате):

```sql
SELECT c.client_id, c.city, c.str, c.dom, cg.geo_updated_at
FROM clients c JOIN clients_geo cg ON cg.client_id = c.client_id
WHERE cg.geo_status = 2
ORDER BY cg.geo_updated_at DESC;
```

**Важно:** используй `mysql --default-character-set=utf8mb4 ...` — без этого флага кириллица выходит как `?????`.

Когда сокращение незнакомо — **не гадать**, проверять через поиск (`улица <X> Минск`), прежде чем предлагать замену. Не всё резолвится: «Ул. Липурина» осталась неразгаданной 2026-07-05.

**Не трогать `clients.city/str/dom`** (это operational-адрес клиента, используется в т.ч. для доставки). Исправленный адрес пишется ТОЛЬКО в `clients_geo.corrected_address` — это вспомогательное поле только для геокодирования.

## Шаг 3 — проверка через Google Geocoding API

Скрипт: [`docs/geo_address_fix.py`](geo_address_fix.py). Тестирует список `(client_id, corrected_address)` через Google Geocoding API и репортит три категории:

- **OK** (не partial match) — можно смело писать координаты.
- **PARTIAL / город-центр** — Google возвращает `partial_match` или падает в синтетическую точку центра Минска (`53.9006, 27.5590` — та же самая, что фильтруется в `geo_heatmap.php`). У Google просто нет данных по этой улице/дому — кандидат на **Яндекс-геокодер** (см. ниже) или ручной разбор.
- **Google «исправил» на другую улицу** (иногда молча подменяет похожее по звучанию, но другое место) — **не доверять**, считать неразрешённым.

```bash
python3 docs/geo_address_fix.py
```

Отредактируй список `records` в начале файла под текущую пачку адресов перед запуском.

## Шаг 4 — запись результата

```sql
UPDATE clients_geo SET lat=<lat>, lng=<lng>, geo_status=1, geo_updated_at=NOW(), corrected_address='<исправленный адрес>' WHERE client_id=<id>;
```

Для тех, что не резолвятся (partial/city-center/спорные) — всё равно можно записать `corrected_address` (без изменения `lat/lng/geo_status`), чтобы при следующем прогоне не тратить AI-время на уже разобранные строки:

```sql
UPDATE clients_geo SET corrected_address='<лучшая догадка>' WHERE client_id=<id>;
```

**Автоматический повторный подхват:** `GeocodeClients.php` при следующей плановой попытке (раз в 7 дней для `geo_status=2`) сам использует `corrected_address` вместо сырых `city/str/dom`, если он заполнен — правка не теряется.

## Когда включать Яндекс-геокодер

4 из 37 адресов первого прогона (2026-07-05) стабильно падают в синтетическую точку центра Минска у Google независимо от формулировки — у Google просто нет данных по этим улицам/домам. Для них имеет смысл Яндекс-геокодер (обычно лучше знает Беларусь) как fallback — код уже готов в `GeocodeClients.php` (fallback на Яндекс при неудаче Google), нужен только рабочий `YANDEX_MAPS_API_KEY` (заявка на коммерческую лицензию подавалась 2026-07-04, статус — уточнять).

## Когда эскалировать на человека

- Пустой адрес («-», «0») — контактировать с клиентом невозможно, оставить как есть.
- В поле «улица» стоит название другого города (напр. «Новолукомль») — это баг данных клиента (перепутан город), не задача геокодинга; передать на ручную проверку карточки клиента.
- Название улицы не находится вообще ни в одном поиске — оставить `geo_status=2`, задокументировать в таблице выше как «не разгадано», не гадать координаты наугад.
