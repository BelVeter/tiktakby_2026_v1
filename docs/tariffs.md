# Логика формирования тарифов аренды

## Модель данных

Тариф — это пара «период ↔ цена за весь период» для конкретного товара. У одного товара может быть несколько тарифов (обычно 3–4).

Поля одного тарифа:

- `model_id` — товар, к которому относится тариф
- `step` — единица периода: `day` | `week` | `month` | `year`
- `kol_vo` — количество единиц периода (например, `step=week`, `kol_vo=2` → период 2 недели)
- `rent_amount` — стоимость за весь период (главное поле)
- `rent_per_step` — производная: цена за одну единицу периода (`rent_amount / kol_vo`)
- `kol_vo_min` — минимальный срок аренды (используется редко)

Конвертация периода в дни фиксированная: `day=1`, `week=7`, `month=30`, `year=365`. Длина периода в днях = `kol_vo * stepInDays`.

Активные тарифы хранятся в таблице `rent_tarif_act`, при удалении/изменении переносятся в архив `rent_tarif_prev`.

## Расчёт стоимости аренды на N дней

Алгоритм (ступенчатый расчёт со скидкой за длительность и потолком):

1. Взять все тарифы товара, отсортировать по длине периода в днях по возрастанию.
2. Для каждого тарифа вычислить дневную ставку: `rentPerDay = rent_amount / periodDays`. Чем длиннее период тарифа, тем ниже дневная ставка (это и есть «скидка за длительность»).
3. Выбрать подходящий тариф для запрошенных N дней — тариф с наименьшим периодом, который ≥ N. Если такого нет (N больше максимального периода), берётся самый длинный тариф.
4. Базовая цена = `N * rentPerDay` выбранного тарифа, округление до копеек.
5. **Потолок**: итог не должен превышать `rent_amount` любого более длинного тарифа. Если превышает — заменить на этот `rent_amount`. Логика: клиенту никогда не выгодно платить за N дней больше, чем стоит более длинный готовый тариф.

Пример: тарифы 7 дн = 50, 14 дн = 85.

- Запрос 10 дней: дневная ставка 7-дневного = 50/7 ≈ 7.14, итог 10 × 7.14 ≈ 71.43. Проверка потолка: 14-дневный тариф = 85, 71.43 < 85 → итог 71.43.
- Запрос 13 дней: 13 × 7.14 ≈ 92.86, но потолок 85 → итог 85.

## Автоматический расчёт ступеней при создании тарифа

Когда админ создаёт основной тариф на 4 недели (`step=week`, `kol_vo=4`), система автоматически генерирует три производных тарифа с прогрессивной скидкой:

- 4 недели: `rent_amount` (база, задаётся админом)
- 3 недели: `база × 0.9` (10% скидка относительно базы)
- 2 недели: `(3-недельный тариф) × 0.85` (ещё 15%)
- 1 неделя: `(2-недельный тариф) × 0.7` (ещё 30%)

Округление специфическое: дробная часть 0.25 → 0, 0.5 → 0.5, 0.75 → 1 (т.е. шаг 0.5).

## Особые режимы

- **Карнавальный/праздничный режим**: для товаров с флагом «карнавал» базовая единица отображения и расчёта — 1 день вместо 3. Меняет лишь презентацию и дефолты, не саму формулу.
- **Множественные ставки** — норма, не исключение: товар без нескольких тарифов лишён скидки за длительность.

## Что должно быть продублировано на сервере

Все расчёты цены при оформлении заказа должны выполняться на сервере по тем же тарифам — клиентским значениям доверять нельзя. Клиент получает прайс через AJAX только для отображения.

## Главное

Тарифы — это **набор «опорных точек» цена↔период** для одного товара. Реальная стоимость аренды на N дней рассчитывается выбором подходящей опорной точки и линейной экстраполяцией дневной ставки, с потолком по следующему более длинному тарифу. Все денежные расчёты дублируются на сервере при оформлении заказа.
